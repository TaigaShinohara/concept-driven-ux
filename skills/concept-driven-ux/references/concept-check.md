# コンセプト達成の最終照合

案件を閉じる前に、当初のコンセプトと最終成果を要素ごとに突き合わせる。判定は「実現／部分的に実現／未実現／未確認」の四つ。根拠には、審査、動作確認、人間の観察のどれで確かめたかを書く。人間が触って確かめる要素で体験確認がまだなら「未確認」とし、AIの照合だけで「実現」にしない。未実現があれば、戻し先（対象選定／役割／内容／行為）を決めて記録し、案件を完了にしない。

```text
対象版：
コンセプトの要素（誰が／どんな場面で）：
  最終成果での実現内容：
  根拠（審査／動作確認／人間の観察）：
  判定：実現／部分的に実現／未実現／未確認
コンセプトの要素（何をして／どんな状態や気持ちになるか）：
  （同形式で要素ごとに繰り返す）
未実現・未確認の一覧と、戻し先または次の確認手順：
```

記入例（架空の読書記録アプリで、積読を減らす改善を行った場合）：

```text
対象版：読書記録アプリ 改善版 v3
コンセプトの要素（誰が／どんな場面で）：読みかけの本を持つ人が、通勤前の短い時間に
  最終成果での実現内容：起動直後の画面で読みかけ一覧と前回の止めた位置が先に表示される
  根拠（審査／動作確認／人間の観察）：動作確認（実機で起動から表示までを確認）
  判定：実現
コンセプトの要素（何をして／どんな状態や気持ちになるか）：迷わず1冊を選んで読み始め、続きが気になる状態で終える
  最終成果での実現内容：候補を1冊に絞る提示と、終了時に次回の開始位置を示す案内を実装
  根拠（審査／動作確認／人間の観察）：審査のみ（人間の観察は未実施）
  判定：未確認
未実現・未確認の一覧と、戻し先または次の確認手順：人間の観察で「迷わず選べるか」を確かめるまで案件は未完了とし、観察手順を添えて渡す
```
